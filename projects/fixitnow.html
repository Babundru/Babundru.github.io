FixItNow

A C++ simulation of a home-appliance repair service — employees, appliances, and incoming repair requests — run tick by tick until every technician's queue is empty, with reports to show for it.

C++OOPSTL Smart PointersCSV I/O
View on GitHub ↗

Key features

01 Polymorphic employee & appliance hierarchies

Employee and Appliance are abstract bases, not tags on a struct. Technician, Receptionist and Supervisor each compute their own salary and behaviour; Refrigerator, TV and WashingMachine each carry their own technical spec — so adding a new employee type or appliance model means writing one derived class, not touching a switch statement elsewhere in the codebase.

02 Two ways to run it

Launched with no arguments it's a menu-driven interactive tool for hiring staff, logging requests and pulling reports by hand. Launched with two CSV paths it does the same work in one automated pass — the mode that made it possible to script test scenarios instead of clicking through a menu for each one.

03 A tick-based simulation loop

ServiceManager advances the whole shop one tick at a time: pending requests are matched to a technician who's both free and qualified, busy technicians count down their remaining repair time, and a request that hits zero flips to Completed and frees its technician for the next one.

04 Skill-aware technician matching

Technicians aren't interchangeable — a skill can be scoped to one brand (e.g. TV, Samsung only) or marked All. Allocation checks both availability and skill before assigning a request, so a Samsung-only technician never gets handed an LG repair just because they were free first.

05 CSV reports on demand

At any point the tool can dump the current state to CSV: pending tasks, per-technician workload and performance, and requests nobody was qualified for — the last one doubling as a hiring signal, since a pile of unsupported requests for one brand is an argument for the next hire.

06 Parsing and hiring that don't trust the input

CSV rows are wrapped in try/catch, so one bad line — a malformed date, a missing column — gets reported by line number and cause and skipped, instead of taking the whole batch run down with it. Hiring gets the same scrutiny: a new employee's CNP is checked for format and checksum, and their age is derived from it and enforced at a 16-year minimum, rather than trusted from a free-text field.

In short

FixItNow is a from-scratch exercise in modelling a real process instead of a toy inheritance diagram — Employee and Appliance are abstract bases so behaviour lives in the subclass that owns it, and shared_ptr threads ownership through every Request without a manual delete in sight. The part that took longer than the class hierarchy was trusting the input: batch mode meant any row of a CSV could be malformed, so parsing has to report and skip a bad line instead of crashing the run, and even hiring an employee means validating a real CNP rather than a free-text age field.
