YouTube Channel Toolkit

Four tools built to run an 850K-subscriber channel without doing everything by hand in YouTube Studio: a React + Electron desktop app for bulk video management, and three focused Python utilities.

React 19ElectronVite PythonStreamlitTkinter OAuth 2.0YouTube Data / Analytics API
TubeClean on GitHub ↗

Key features

01 TubeClean — bulk video manager

A React 19 + Electron desktop app that logs into a channel, pages through the entire uploads playlist 50 at a time, and shows every video as a selectable card. The OAuth flow is a real desktop one — the main process opens the system browser and exchanges the code, so the renderer never touches the client secret. Sessions persist across launches.

02 Handles the API's daily quota

Deletion is expensive against YouTube's quota. Rather than surfacing a raw quotaExceeded error, the app detects that reason code and shows a live countdown to the reset at midnight Pacific, converted properly rather than hardcoded.

03 Uploader

A Streamlit front end over the Data API's resumable upload endpoint: drag a file in, fill metadata, publish now or schedule (local time converted to UTC automatically). Uploads are chunked and resumable with backoff, so a 4GB file doesn't restart on a blip.

04 Analytics dashboard

Pulls channel performance for a date range into four tabs — core stats, engagement, revenue, cards. Each group is queried separately on purpose, since the API rejects some metric combinations and revenue needs a scope you may not have; one failing group doesn't take the others down. Exports to CSV.

05 Title changer

A minimal CLI for fixing a title without touching anything else. It exists because videos.update replaces the entire snippet — send one containing only a title and you've just erased the description, tags and category. So it fetches the current snippet, mutates one field, and round-trips the rest untouched.

In short

These are the projects where I was my own user, and it shows in the error handling — every non-obvious state has a screen that explains it, because I'm the person who hit each one at 1am and had to work it out from a raw JSON error. Working against someone else's API is mostly about respecting its constraints: the quota is finite, uploads fail mid-flight, update replaces rather than patches. I picked the stack per tool rather than per developer, which is why one is Electron and two are 200-line Python scripts.
