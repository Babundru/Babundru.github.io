Signal vs. Noise

Our entry for Hackitall 2, a Procter & Gamble challenge on corporate search. An eight-layer pipeline that reads news about a company, scores how much of it deserves to be believed, and radars supply-chain risk.

FastAPIspaCyPydantic OpenRouter / GeminiSerpAPILeaflet
Team repo — private to the hackathon organisation

Key features

01 An eight-layer pipeline

Scrape and NER → URL trust classifier → signal scorer → claim classifier (fact / inference / opinion) → verification against past analyses → composite trust score → risk radar → persistent company memory. Each layer is a separate module with one job, and the whole response is a typed Pydantic model.

02 A trust score that isn't a vibe

The final score is an explicit weighted sum — 30% source reputation, 30% signal density, 20% claim type, 20% verification status — rather than a number asked of a model. That means it can be argued with: a low score reads as "unknown blog, low signal density, opinion, single-source", not "the AI is unsure".

03 Context windows, not raw text

The signal scorer builds a ±3-sentence window around every financial trigger term, and those are what the LLM receives. It strips boilerplate, cuts token cost enough to make a ten-source run feasible, and gives the model concentrated evidence.

04 Risk radar with negation

Five risk categories scanned without the LLM, so the signal doesn't inherit its failure modes. "Avoided bankruptcy" and "declared bankruptcy" share a keyword, so a negation factor zeroes denied risks — and surfaces them separately as strengths.

05 Geographic risk mapping

Location entities from the NER pass are attached to the risks that mention them and plotted on a Leaflet map, colour-coded by severity — so a supply-chain risk reads as a place, not a row.

06 Human-in-the-loop and memory

Keyword-driven detection produces false positives, so every risk row has a button that permanently down-weights that anchor — 10% per report, capped at −70%, so a term can be de-emphasised but never silenced. Meanwhile each company's profile persists between sessions, and only gets overwritten when the model returns something more specific, so a thin article can't wipe a good profile.

In short

The obvious build — scrape news, feed it to an LLM, print the summary — fails because the internet lies at different rates depending on where you're reading, and a Reuters piece and an anonymous blog post produce equally confident summaries. So we inverted it: source reputation, signal density, claim classification, corroboration and risk scoring are all deterministic code, and the model only does the reading comprehension. That split is why every number on screen traces back to the layer that produced it.
